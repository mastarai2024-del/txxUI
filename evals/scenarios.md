# 行为走查情景

用于维护技能时检查决策；这些条目本身不是 MasterGo 运行或验收证据。

| 场景 | 应采取的行为 | 不应发生 |
|---|---|---|
| 用户说“去莫高拿最新设计图” | 将“莫高”识别为 MasterGo；定位对应需求的源文件、页面和最终版画板，回读节点并导出原生截图 | 要求用户改用英文名，复用旧飞书配图或 HTML 作为最新设计证据 |
| 从 PRD 画新页面，用户已指定目标 | 首个 MasterGo 动作进入 design_page；按当前流程读取来源并固定目标 | 先自行询问来源、遍历全部库、默认写到来源页 |
| 新 PRD 设计未指定目标，当前选中历史测试页 | 在 design_page 允许阶段按需求名新建独立画布，确认标识后写入并登记归属 | 默认写当前页，查找或硬编码“测试尝试”，每个手机界面另建文件 |
| 同一任务补充状态，已有 PRD 与画布映射，当前打开来源页 | 核对映射后切回已有目标画布补画 | 每次调用都新建画布，或在来源页落稿 |
| 同一产品项目，改为另一份 PRD 的其他需求 | 新建该需求的画布，规范与素材仍可复用 | 因为同一产品而把所有 PRD 设计堆到原画布 |
| 用户明确要求将另一份 PRD 画到指定既有页 | 以用户指定目标为准并更新映射 | 用默认新建规则覆盖用户指定位置 |
| 同名画布缺少任务归属，或工具无法创建/定位目标 | 新设计不按同名复用；按规则新建，定位失败则报告阻塞 | 猜测同名即同任务，或向其他需求/来源页兜底写入 |
| 自由绘制但要求严格照原稿 | 保留完整结构和真实素材，补最小必要增量 | 重新设计首页或只保留配色 |
| 只说“看看哪里有问题” | 只读检查，列具体发现 | 自动批量改稿 |
| 已授权统一菜单，当前有表单和结果提示 | 同类菜单统一，表单保持可读，结果提示按语义处理 | 所有文字居中、所有状态一律加遮罩 |
| accepted 后截图仍旧，或请求超时 | 遵守当前门禁，记录未知状态并对账 | 同时重发 MCP、原生粘贴和全量覆盖 |
| 队列已满且明确拒绝最后一条 | 等已受理请求完成，只重提被拒绝条目 | 重放整个批次 |
| 需要独立图片副本，源文件只读 | 复制实际图层，仅解绑目标，验证目标素材归属 | 改或删真实来源来试验 |
| 临时图片 URL 变灰框 | 查真实图层和持久性，采用支持的导入或原生复制 | 反复更改内部 revision URL |
| 当前工具要求提交后停止或 QA 确认 | 如实交付“已提交待验收”，等待对应用户决策 | 睡眠后从其他工具偷做自动 QA |
| 菜单取消顺序错、拖动柄仍偏左 | 回读当前节点；修局部容器布局并截图 | 只看代码属性就宣称修好，或全量重建整页 |
| MasterGo 完稿，但 HTML 与文档还是旧版 | 交接最新映射，并分别报告版本及授权范围 | 默认覆盖飞书，或声称三端都已更新 |
| 要公开技能 | 只发布脱敏规则和可复用资源 | 带上业务截图、原始聊天、私有地址和本机路径 |
| 新电脑调用txxUI设计页面，未安装Taste | 自动运行ensure_taste.py，安装并校验完整目录，读取返回的SKILL.md，再进入相应设计分支 | 只下载入口、默默跳过、要求用户另行手动装技能 |
| Taste已完整安装在共享skills/taste-skill目录 | 直接复用并读取；不下载、不升级，不创建重复安装 | 只认固定目录名，重复安装或覆盖原技能 |
| 已有Taste目录残缺或离线安装失败 | 保留原目录，报告缺失/网络错误；继续独立的已授权读取，设计保持待完成 | 覆盖用户目录、声称已调用Taste、无限重试 |
| 既有App有独立规范，用户只要求样式和按钮对齐 | 读取规范画板及同类组件，使用Taste的App适配检查；只改相关属性 | 抽随机配色、改品牌风格或把网页禁用规则覆盖到项目 |
| 无规范的营销网页，获准完整设计 | 使用Taste内容论证、方向与素材流程，提交语法仍服从MasterGo | 把App适配流程当成完整Taste，或为静态稿强制生成网页代码 |
| 修改照片容器和弹层，回读高度/层级未生效 | 样式属性去重，明确实际高度，检查后续文字、遮罩和取消按钮的截图 | 重复height互相覆盖，或只凭top/z-index代码判断通过 |
| Taste要求截图循环，但MasterGo生成后要求停止或QA确认 | 停在当前工具阶段，报告待验收 | 借Taste名义绕过QA或停止门禁 |
| 操作菜单每项都有复述动作的灰色副标题 | 保留明确动作名，去掉无新增信息的说明，按单行动作重算行高和弹层高度并检查截图 | 仅把副标题缩小、变淡、藏入tooltip，或删字后留下双行空位 |
| 删除项说明影响范围，且已有删除确认 | 核对真实需求和确认文案；保留确认内必要后果，菜单只留作决定所需的信息 | 为简洁漏掉风险、虚构永久删除或相关数据范围、擅自改变确认步骤 |
| 当前菜单直接执行不可逆操作，没有后续确认 | 保留执行前必要警告；在现有流程内整理层级 | 套用单行规则删掉唯一警告，或擅自增加流程 |
| 设置项展示当前值，付费动作展示费用，选项说明真实差异 | 保留影响选择的信息；按组件规范排版，触屏可读 | 把所有第二行一律视为AI痕迹删除，或在其他普通动作下补齐副标题 |
| 学设计师画风，保留已有布局，来源页上方为原型、下方正式稿 | 只读采样正式根节点；迁移控件/字体/色阶/内部关系，保留屏内布局与画布编排 | 调用design_page重画、整页坐标照搬、把上方原型纳入语料 |
| 最新版V2区域同时放Before、After和AI副本，多个根ID前缀相同 | 按实际版本区域、用户指定作者和节点用途准入；归属不明先排除 | 凭V2页名或ID前缀全量放行 |
| 同一密码控件有十个状态，另有两个不同家族 | 重复状态共享family，分别记录出现次数和独立家族数 | 将十个副本计为十份独立证据，自动把高频值宣布规范 |
| 源稿错字、错误动作名、11px淡字、保存按钮压到系统区 | 文案按需求校对；明确记录可读性/安全区修正，学习外观与内部关系 | 把错误文字和绝对y值写成必须复刻的风格 |
| AI密码控件已与设计师相同，AI说明文字更清楚 | 记录一致项并复用；保留更易读的说明，针对真正差异改进 | 为显示工作量重画正确控件或一律缩小文字 |
| 灰色分别出现在按下、禁用与未选中状态 | 按状态语义和规范分别取值 | 统一成一个灰态或把opacity .5套到所有状态 |
| 规范用28px标签列出14/12/11字号，SVG隐藏卡片圆角 | 解释规范内容，区分展示属性；SVG缺失值记未知并补证 | 将28当正文规范，凭截图补造精确圆角 |
| Bubbo新页面与另一款无关App分别发起设计 | Bubbo核对项目档案和相关锚点；另一项目建立自己的基线 | 把Bubbo的色值/控件尺寸当技能全局默认 |
| 已有风格档案，续做仅修改配网表单，源稿发生局部变化 | 刷新配网家族与相关截图，复用未变化档案；同任务Taste只准备一次 | 重读全部历史页面，或不核对来源而永久使用旧缓存 |
| 跨页批量截图部分成功、部分页面不匹配 | 保留已成功项，按完整来源身份处理失败项，报告实际覆盖 | 把部分成功当全部完成，模糊选取目录首图 |
