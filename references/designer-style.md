# 从设计师定稿继承风格

现有项目的新页、局部视觉修改，以及 AI 稿与设计师稿对比时使用。目标是让新增部分属于同一套产品：先继承同场景的结构与组件，再处理本次需求的差异。只读回贴截图不需要重做风格分析。

字体 family 统一按 [字体统一规则](../SKILL.md#字体统一规则) 执行：中文思源黑体，英文和数字钉钉进步体；来源稿的旧字体仅作为观察记录。字号、行高、字重角色及其他视觉属性继续按本页方法提取。

## 1. 选对样本

先按用户当前确认锁定设计师最终稿，再核对文件、页面、容器和状态。用户用灰色外底板、日期或区域标记版本时，只将它们作为本项目的定位线索；区分画布底板与手机画板内的产品背景。

进行 AI/设计师风格对比时，按**同页面、同状态、同组件**配对；普通改图直接读取最终源稿，不必寻找历史 AI 稿。内容不同的两页先区分需求变化，再比较共同结构。设计师保留的布局也是证据，不为体现优化而全部重排。只有单侧样本时可描述该稿，不能归因“设计师改了什么”。

当前用户已否定的样式从基线中排除，即使它出现在设计师稿中。PRD 和当前确认决定功能、文案与状态，设计师稿决定已确认的视觉；发现矛盾时记录具体项，不从图推导新业务规则。

## 2. 提取可执行的角色表

从原生节点读取数值，并结合截图看实际结果。将提取结果保存在项目任务记录，写明来源节点、观察日期、适用组件与状态；截图可见的判断、原生属性和未确认项分别记录。

| 维度 | 提取与继承 | 常见偏差如何收敛 |
|---|---|---|
| 信息组织 | 主操作、当前值、必要帮助、分组关系；说明靠近对应控件 | 不给每个动作补副标题，不将两句帮助升级为两张提示卡；删减已获准的说明后重算留白 |
| 排布与对齐 | 页面外边距、卡片宽度、内边距、文本基线、行高、行间距及控件锚点 | 先看同类行是否对齐，再看整页；正文/表单、导航标题、操作菜单和尾部值各沿用其角色对齐 |
| 字体 | 实际 family、字体样式、字重、字号、行高和中英文/数字组合 | 新增标题、按钮和帮助文本按统一规则设置字体，匹配同角色字号、行高与字重；保留中文/数字/符号的字体切分，不只继承父容器，避免新增部分落到工具默认字体 |
| 图标 | 真实图标来源、尺寸、线宽、端点、填充/线性、颜色、视觉中心 | 优先复制项目已有返回、关闭、箭头、状态图标；必要新增时匹配同族，不能混入 Emoji 或近似库图标 |
| 颜色 | 页面、卡片、主文字、辅助文字、分隔线、开关、危险/禁用态的角色 | 区分纯黑、带透明度的黑与灰值；同角色保持一致，避免一组控件里深浅不一；不为装饰加入新品牌色 |
| 组件 | 卡片、输入行、胶囊标签、开关、按钮、弹层分别记录圆角、尺寸、描边及阴影 | 按组件类型继承；底部弹层的圆角不推广到普通卡片，按钮宽高正确时保留，只修实际不一致属性 |
| 素材与示例 | 真实头像、照片、二维码、对话气泡及其裁切与排列 | 保留产品资产和真实对话结构；不用文字徽标或灰框近似替代已有资产 |

用逻辑尺寸比较。截图是二倍或三倍导出时，先核对画板尺寸与导出倍率，再换算；不要把整张截图宽度直接当 UI 宽度。字体 family 无法从图片可靠辨认，必须读原生文本及其片段；倾斜可能来自所选字体，也可能是加载异常，先核查属性再判断。模糊、错字或局部异常未经确认不固化成设计偏好。

表中记录的是**角色及关系**，不是全局固定数值。字体 family 按统一规则；具体字号、绿色、灰度、圆角、边距和画板尺寸只适用于有来源的项目/组件，下次进入其他项目重新提取。

## 3. 用组件保持一致

同场景已有合适组件时，优先完整复制其容器、文本、图标与素材，再改获准的文案、值或状态。沿用真实行高、内边距、圆角和系统区域，比重新拼一个外观相似的卡片更可靠；仍按当前工具路由处理目标与实例独立性。

新功能需要新结构时，从设计师稿的同类角色组装：设置行参考设置行，表单参考表单，确认框参考确认框。先确定内容如何分组，再选组件；不要用装饰性卡片填满屏幕空白。开关/按钮的位置与触控区域沿用项目，文字变长优先换行并计算内容高度。

复制组件后在获准目标范围落实统一字体，并按当前工具要求加载可用字体、使用精确 family 与字重。字体缺失或回退时明确报告并修正可修部分；不得静默替换，也不可将代码里写了 family 当作字体已正确呈现。

帮助文字保留用户作决定所需的信息：设置的开关后果、当前值、权限/费用、必要警告。可简写成行内的一句或现有组级说明；具体位置服从当前确认，不自动发明可关闭提示框、信息图标或新确认步骤。

## 4. 同尺寸检查

在当前工具允许的验收阶段，用同逻辑尺寸的最新原生截图并排检查源稿与目标。先看分组、内容密度和主要锚点，再看字体/灰度、图标、圆角和素材；小改只看受影响区域及相邻边界。

逐项说明“保留、改变、未确认”：设计师稿正确的结构应保留；本次新增部分应与同角色组件一致；用户明确要求的变化应出现。发现不同先分清是需求差异还是风格偏差，再修后者，避免把新需求改回旧稿。

最低可观察结果：同角色文字及中文/数字/符号片段的字体与基线一致；同类行的文本与尾部控件对齐；必要说明可读且未裁切；圆角与颜色匹配组件角色；图标和真实素材正常；最新截图与实际节点对应。两份截图中内容不同的区域不做像素相似率结论，结构回读也不能替代视觉检查。

通用技能只保存方法与脱敏案例。具体项目的节点链接与截图进入项目记录；已提炼的项目画像可独立存放并注明适用范围和观测日期，后续先核实来源是否更新；没有对应配对证据时，不用“人类设计师都这样”概括风格。
