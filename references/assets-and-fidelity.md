# 素材、图层复制与原稿还原

## 灰框先查什么

先看实际画布，再看目标节点：

1. 应该是图片的节点是否仍是单色占位框，是否有图片填充或有效图片节点。
2. 资源来自目标文件内存储、稳定素材库，还是本机服务、临时会话或带时效的 URL。
3. 是否被透明度、混合模式、裁切、遮罩或图层顺序遮住。
4. 是否选中了错误版本、错误头像或同名图层。

不能把颜色值为灰色的所有矩形都判成缺图。不能仅凭导出的 `src` 或 HTTP 成功就说图片已可用。

## 用户要求“直接复制，不依赖来源”时

### 复制前

- 记录来源文件/页面/节点及其截图，确认来源只读。
- 对复杂头部、导航、状态卡，优先复制完整图层组，保留背景、旋转、相对坐标、字体、混合和裁切。
- 判断需要普通图层副本、组件实例还是图片素材副本。用户要求独立时不要保留跨文件组件依赖。

### 原生复制步骤

1. 选中来源的实际图层，确认选区名称和范围。
2. **复制**，不剪切，不改来源属性。
3. 切回白名单目标页面，重新确认目标文件、页面、父容器。
4. 粘贴，读取新节点及归属，按目标画板尺寸摆放。
5. 仅在目标副本上解除需要解除的实例关联、裁切或调整尺寸。
6. 先检查一处成功，再复制到其余相关状态；每处保留来源到目标的映射。

没有适用复制能力时，可通过当前工具支持的素材导入方式把文件真正导入目标。导入超时先查目标有无结果，不自行拼接内部版本 URL 或依赖未公开的服务端写接口。

### 独立性验收

证据至少包括实际图像正常、目标拥有对应节点/素材，以及所需的组件关联已解除。没有外部 URL 只是辅助信号，不能单独证明独立。

如果为了操作创建了本次专用的临时来源副本，在确认正式稿已独立、清理已获授权后，可以删除这些临时副本，再重新打开或截图正式稿。**不删除真实来源文件、页面或他人的图层来做验证。**

无法验证底层素材归属时，写清已验证显示、未确认持久独立性；不要把“现在能看到”升级为永不失效的承诺。

## 共享关系与修改范围

先确认目标是主组件、实例、普通副本还是独立状态，不能凭同名容器判断关联。只改单页时，保留共享来源，通过获准的目标属性覆盖或独立副本完成。用户明确要求修改共享组件时，核对主组件及受影响实例均在授权范围，再改指定文字或属性；不批量解绑，也不逐页重造已正确关联的组件。

改后检查关联实例中的覆盖值、不同宽度与换行，以及脱离关联的独立状态。共享文案一致不代表各页开关、资格或弹窗状态也应相同；导出并交接实际受影响的全部状态。

## 还原复杂区域

本次实践中，逐项重画头部造成背景缺失、三行斜排文案被拉直、设备状态卡简化。复制完整原稿组后才恢复完整效果。

检查完整性时按区域核对：

- 背景是不是同一张图，裁切和混合模式是否相同；
- 标志、通知点、设备头像、电量图标、分隔线有没有遗漏；
- 旋转角度、文字错位和行距是否保留；
- 导航宽度、边距、选中态和系统手势条是否正确；
- 同一个首页的多个状态是否都更新了，而不是只改第一张。

只读原稿可以有比目标更长的画板。复制到手机视口后要复查父容器、裁切范围及底部定位，不把原图高度当目标高度。

## 资产核对的边界

- 位图文件引用、尺寸或哈希比较有助于发现意外换图，但不能替代视觉检查。
- SVG 导出名或哈希可能随导出上下文改变。先比较节点身份、路径/样式与实际形状，不因为名字变化就重建图标。
- GIF、动态素材和文字栅格化会造成截图差异。做同尺寸对照并描述差异来源，不把平均像素差当作设计合格分数。
- 原图只能作为图片内容使用；将整张 UI 截图铺进画板不满足文字和控件可编辑的交付要求。
- 用户要求原文不变的截图或素材，清晰度处理后逐项核对文字、数字、日期和淡色内容；不补写模糊信息，不把重新生成的相似图当原始证据。无法确认的细节保留并说明，不能只凭更清晰就通过保真检查。

## 导入后形状与源文件不一致

用户反馈圆形变椭圆、图标缺边或旧图未更新时，先分别看源文件和目标画布，确认实际引用版本。源文件检查可见轮廓、透明边界及 SVG 的 viewBox/变换；目标检查图层宽高、填充缩放、裁切、蒙版与旋转。画布尺寸相同不保证图形本身是正圆，提高导出分辨率也不能修复拉伸或错误引用。

按已定位原因修正获准的目标或文件，保留透明度和比例，再核对导入后的显示。若仅交付新文件且无法读取目标图层，写清“本地已检查，画布未验证”；不因换了文件名或本地截图正确就宣称目标已修复。
