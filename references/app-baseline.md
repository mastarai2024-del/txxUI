# 从运行页面建立设计基线

巴布 APP 默认使用此流程；其他项目在用户已指定运行应用为设计来源时采用。运行页面提供现状，当前确认的需求决定变化，txxui 将变化落实到获准设计目标。评审保持只读；纯回填已有图只核对来源与状态，不因此启动改图或完整路径走查。

## 找到入口并固定版本

先从本机个人上下文、项目记录或用户当前提供的链接定位模拟 APP；已登记且可用的入口不重复询问。首次核对当前运行版本，续做只检查受影响页面和来源是否变化。读取模拟 APP 不改变“新页面的首个 MasterGo 动作为 design_page”的工具路由。

| 来源 | 用途 | 核对与限制 |
|---|---|---|
| 当前交互手机 / 运行页面 | 现有布局、控件、可见状态及实际入口与返回 | 构建标识、平台、逻辑尺寸及相关模拟状态；只证明本次实际观察 |
| 页面导航图（Atlas） | 找页面、关联入口、候选截图与源码位置 | 单独记录日期与来源版本；截图可能沿用旧采集，调试、保留和停用页面不等于正式可达 |
| 对应源码 | 核对组件参数、素材、路由、触发条件与实现出处 | 仓库、分支/提交及相关未提交变化须与运行构建对应；有源码路径不等于本机已有源码 |

在现有任务记录中保存本次用到的运行地址和构建标识、对应源码版本及受影响文件、页面/状态、进入与返回路径、逻辑尺寸和截图。未获取项写明未知。编译后的 Web 预览包不冒充可编辑源码；构建含未提交改动时，提交号不能单独确定完整基线，保留构建标识及可核实的差异来源。

导航图与交互手机版本不同，先用导航图定位，再在当前交互手机核对实际页面和相关操作；没有重走的连线保持未核验。当前需求或已确认设计尚未进入运行版本时，保留运行页作为修改前基线，按确认内容做增量，不把新规则改回旧实现。其他来源冲突具体列明，影响方向、入口或业务规则的缺口才集中澄清。

## 从真实控件进入

绘制或修改前，走本次涉及的“父页面 → 触发控件 → 目标页/弹层 → 相关操作结果 → 返回”。记录对象、Tab 和相关条件，核对返回后的对象及选中状态；任务涉及滚动位置、即时保存或取消时再检查这些结果。局部任务只覆盖相关路径，不遍历整套 APP。

直达路由、导航图连线和可打开的独立页面都不能单独证明真实入口存在。只在调试菜单、预览控制栏或停用页面出现的入口，不画成正式用户入口；不得把页面分类直接转成顶层导航。纯视觉评审读取对应页面与组件即可，仅在评审涉及入口时走相关路径。

没有对应新页面时，从最近的真实入口页、同模块骨架与组件扩展，标清已有部分和新增设计；新增入口、保存时机、条件及结果由当前确认决定，不能凭相近页面推断。

## 继承页面并逐模块整理规范

先复用对应页面的结构、系统区域、真实素材、导航、内容分组与操作区，再修改获准部分。已有匹配的 MasterGo 图层可原生复制到目标；只有截图或运行页面时，按核实的布局与参数建立可编辑图层，不能用整页截图冒充可编辑设计。

有对应源码时，读取相关组件、主题与素材引用；没有源码时，截图和实际操作可支持其可见范围，精确字体、间距或条件等未读到的属性保留未知。源码中的条件还需区分模拟分支与正式逻辑，不能把演示数据和延迟固化成业务规则。读取来源不授权修改源码、服务或原稿；只有明确要求前端/HTML 时才进入相应交付分支。

按本次涉及的页面和组件角色整理布局、颜色、字号/行高、间距、圆角、图标及素材，注明来源版本、状态、适用模块和证据类型。源码/原生节点数值、截图估计及未确认项分开记录。参数留在项目私有规范或现有任务记录，后续设计仍核对当前相关页面；不把某个旧模块的数值、画板尺寸或风格画像推广到全 APP，也不为小改重建完整设计系统。

字体继续遵循[字体统一规则](../SKILL.md#字体统一规则)。运行页面实际字体另作观测；发现差异时记录受影响的文字角色、属性与渲染，按既有字体规则处理获准目标并说明差异，需要改变字体要求时再确认，不静默覆盖。字体清单仅证明携带字体，不证明各页实际使用；未解决的差异不能宣称与 APP 完全一致。

## 对照、缺口与交付

### 全量 UI 图库

用户明确要求全量还原时，按当前真实导航组织主分区和独立登录／前置流程；分区下再按页面层级、业务模块和条件状态建清单，不把导航图节点数当应画页数。分区、模块用可编辑名称标在画板外，图层树与画布分组对应，组件库单独放置。整理布局保留已交付图层与画板，移动分组后重新核对父子归属、相对／全局位置、遮挡及名称，避免旧节点 ID 或坐标继续误用。

长页面不能只还原首屏：检查协议正文至末段、长表、滚动区域和底部操作；用项目认可的长画板或连续状态表达，不能为凑齐数量留空白正文。条件弹层、系统权限和不可达状态按实际证据列覆盖或缺口，不用近似页面冒充。总览、逐页视觉、可编辑结构与功能状态覆盖分别核对，不把已核对布局写成全量细节通过。

“已与线上源码同步”需要核对当前线上来源与版本，并有对应源码或可核实差异；历史一次可达、编译包提交号或下载成功只能证明各自范围。后续来源不可达时保留已核实版本和遗留项，不继续声称当前线上最新。

### 局部改动与交付边界

保存当前页面的可靠前图及相关状态；按同页面、同状态、同逻辑尺寸与倍率，对照设计目标的结构、素材、文字、裁切及底部操作区。运行页面截图与 MasterGo 原生图分别标明来源；设计目标的修改前后图继续按[配对要求](layout-and-review.md#修改前后配对)保留，不混作一组来源。

核对设计中的入口与返回是否对应已观察路径，新增或迁移的部分是否符合本次确认。有交互原型交付时，在原型容器走完入口、操作、返回和结果。运行基线的已有路径通过，不证明新设计已经在 APP 实现；MasterGo 图层、视觉、原型和真实 APP 分别记录验收。

服务打不开、需登录或缺少源码时，先利用已授权且可用的来源；不自动更新预览、修改服务或翻找凭据。可继续的部分沿用可核实的同页面版本，并标明覆盖与缺口；关键入口或结构无法确认时，保留独立进展并索取必要来源，不凭印象补图。普通控件小改不因缺少完整源码或全套页面而一律阻塞。

项目源码、编译包、页面资源、截图、模拟数据、私有地址、凭据和填好的项目记录留在私有位置。技能仓库仅保存通用流程、空模板与脱敏示例；维护或获准推送技能时，逐项检查变更文件，不把业务来源带入 GitHub。
