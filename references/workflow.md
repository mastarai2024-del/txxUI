# 从需求到 MasterGo 完稿

适用于多状态绘制和按原稿补入口。局部修改不必重走整套流程。新页面生成先遵循 SKILL.md 中的工具路由，再在工具允许的阶段完成以下工作。

## 1. 分清输入分别决定什么

| 输入 | 决定的内容 | 需要核对的地方 |
|---|---|---|
| PRD | 功能、条件、权限、前后结果、验收边界 | 当前修订、被删除或划掉的规则、未决项 |
| 交互原型 | 入口、页面转换、返回路径、状态变化 | 是否只是演示开关；是否能从真实控件进入 |
| 用户指定的最终 UI | 结构、素材、组件、字体及视觉细节 | 来源文件/页面/节点、真实版本、同模块状态 |
| 现有 App 截图 | 当前菜单和控件形态的补充证据 | 平台、分辨率、系统栏；是否被用户指定为本轮基准 |
| 设计规范 / 组件库 | 可复用的 token 和组件状态 | 是否属于当前项目，是否被选中，是否与当前原稿冲突 |

业务与视觉来源冲突时说明具体条目。不能凭“V2”“After”字样就认定最新；以用户当前指定及实际内容为准。没有现成设计系统的新项目，记录缺口和用户允许的新设计范围，不强行寻找不存在的规范。

只回填最新版截图时，结合用户截图、文件／页面／容器、日期标记和实际画面定位。图层名称或编号错了，按内容匹配并在任务记录注明，不修改来源来凑编号。加载、失败、保存中等状态要与当前规则一致；发现原图自相矛盾时列出具体差异，不从图反推新业务规则，也不借回填请求修原稿。

分别记录“本期已确认范围”和“最新版设计内容”。用户保留旧入口、只同步新内页时，排除未确认的首页或新导航；不能整组照搬。缺失状态不拿近似页替代，只有用户明确允许时才交由 txxprd 使用已核实版本的 HTML 补图，并标明不同来源。用户明确改为仅维护 HTML 时沿用该交付，不补建无需求的 MasterGo 页面。

分阶段任务记录当前授权。与 txxprd 同任务时使用同一份现有任务记录及本轮变更，连同确认来源、替代的旧规则、受影响状态和引用一起维护，不复制出另一份当前口径。用户要求“先改 UI，确认后再回贴”时先交付预览；续做核对后续消息，明确批准回贴后继续读取最新文档并完成同步，不因旧状态仍写“待确认”而重复询问。当前明确暂停时保存已完成、剩余项和精确目标，等待恢复指示。

## 2. 建立页面与状态清单

多模块任务先理清页面关系：各模块从哪里进入、操作或权益属于哪个账号/设备/人物、哪些流程共用、完成后回到哪里。文档中的并列业务分块不直接变成并列 Tab；沿用已确认的导航，不因共用支付或订单就合并不同权益。

先把文档里的重复截图合并为状态，不机械地“一张图生成一页”。至少识别：

- 来源页面和触发入口；
- 操作菜单、编辑/选择、确认、结果；
- 取消或返回到哪里；
- 需求中确实存在的失败、空状态、选中/未选中和条件展开。

有多个入口或 Tab 时，按“入口 → 选中 Tab → 本次相关状态 → 返回”核对。只有 Tab 标签或详情页，不代表对应选中页已画；共用内容的页面外壳、选中态、对象和返回上下文仍可能不同。原型中切换权益或购买后，检查未涉及的账号/设备状态保持原值。

例如“删除一条内容”可以是：内容列表 → 真实更多入口 → 操作菜单 → 删除确认 → 列表移除及结果提示。是否需要原因、是否可跳过、是否保留原内容由 PRD 决定，不能由 UI 绘制者补造。

给每个状态稳定的序号、用途、来源及目标节点，明确哪些是已有页面副本、哪些是新增状态。所需画板数量由清单决定，不固定为案例中的数量。

联动规则只展开本次相关的默认值、全局／个人范围、权限变化、启动前拦截、运行中中断及退出恢复。总优先级不等于已确认中断范围，示例输入也不代表所有系统提示的规则；缺口交给需求确认。用户纠正后检查所有受影响状态，避免旧默认值、例外或恢复逻辑留在图中。

将“功能开关关闭”和“没有使用资格”分别核对。全量开放或免费体验只移除本期不适用的锁定、购买拦截和到期限制，不把所有开关改为开启；未确认结束时间时，不补有效期、倒计时或永久有效承诺。类别标题、权益名称、体验标签和开关说明各有用途，改标签不连带改类别名。

对开关和表单，按实际入口核对保存发生在哪一页、何时生效。仅改样式不移动功能入口；已确认切换即保存的设置，不套用其他编辑页的保存按钮或取消逻辑。需要确认即时保存时，连同失败反馈、返回与父表单的影响交给需求确认，不能仅因当前页没有保存按钮就自行推断。

状态标记按已确认的判定依据绘制。按当前值是否相同判断的“跟随全局／已单独设置”，不等于历史上是否手动改过，也不自动改变继承规则；核对相同、不同、改回一致、未保存或失败的状态。分页批量选择则区分已加载与当前屏幕可见，分别核对原记录、新记录和总控标记，不把取消总控勾选画成全部记录取消。

## 3. 锁定目的地与来源

按 [画布归属规则](../SKILL.md#画布按任务与-prd-归属) 决定新建或复用。此处“画布设计稿”指承载一项需求各个界面/状态画板的独立 MasterGo 页面；文件、页面与画板按当前界面的实际层级识别。不要把每张手机界面分别建成一个文件。

先用已知的 PRD 链接/标识、任务记录及目标映射核对归属。同一任务、同一需求的续做复用原画布；同一产品下另一份 PRD 的其他需求新建画布。没有可确认的既有归属时，新设计默认新建，不把当前选中页、同名页或历史测试页直接当目标。明确修改现有节点或用户指定目的地时，沿用该目标；只读评审无需建画布。

所有新画布必须置于当前项目的「AI绘制」下。先核对实际页面树、父级 ID 和需求页面的归属，再创建或粘贴；不能只凭名称判断。若缺少该层级，先在已确定文件中建立，权限不足时停在具体阻塞。新画布用“需求名 / 模块名 · UI 设计”等能识别需求的名称；重名时加 PRD 短标识或日期。在已确认文件的「AI绘制」下新建需求子页面，不因新增需求另建产品文件。若文件尚未确定，利用现有上下文和当前工具能力确认；缺失信息确实影响归属时才澄清，不在无关文件中落稿。

全新页面设计时，首个 MasterGo 动作按入口的 `design_page` 路由，在工具允许的阶段创建或切换目标。提交前记录并确认实际文件、页面名称与标识；把工具接受的精确标识带入生成/提交，工具不支持定位参数时通过原生界面确认当前位置。若工具自动落到其他页面，先纠正目标再写入；无法创建或定位时报告阻塞，保留已完成的需求整理，不向来源页或其他需求画布写入。

在任务记录中保存 PRD → 任务 → 目标文件/页面的映射，以及新建/复用理由，供后续续做判断。画布确认后再登记写入白名单。

来源图层只读。不要在来源页面调整大小、颜色、裁切、文本或实例状态。需要复制时，复制后立即回到目标，确认父容器、画板和新节点；不要使用剪切。

页面、子页面、画板是不同层级。用户说“下面添加子页面”时，确认创建的是所需层级；不要把多张手机画板误当作多个文件，也不要移到未授权分类。

## 4. 建立视觉基线并应用 Taste

按 [设计师风格](designer-style.md) 锁定当前用户认可的最终稿，提取同角色组件的原生属性及截图证据；只有对比任务才与同页面/状态的 AI 稿配对。项目规范、最终稿、同模块的菜单/表单/确认框共同建立本次基线。只读回贴不重做风格设计。

调用入口中的 Taste 依赖与读取流程，按 [Taste 适配](taste-integration.md) 使用与页面类型相符的方法。Taste 用于判断层级与细节，字体 family 按 [字体统一规则](../SKILL.md#字体统一规则)；字号、行高、字重角色、配色和组件形态按项目基线继承。规范与当前指定稿冲突时记录具体属性；本次明确的局部修正直接按用户要求执行，其他未决差异不擅自扩展。

## 5. 选择最小改动的绘制方法

- 原页面只需补一个更多入口：复制完整原稿到目标，添加入口和新状态。
- 复杂头部已有准确图层：复制完整组并保持顺序、偏移、旋转和裁切，不重新拼近似图。
- 纯新状态：沿用同模块组件及 token，在当前工具流程中生成。
- 图片和图标已有素材：复用实际资产；占位图必须明确是草稿状态，不能当完稿。
- 用户要求独立副本：按 [素材与还原](assets-and-fidelity.md) 处理关联。

每个新页面单独提交。同类页扩展前，先将代表页的导航、字体片段、卡片角色、真实素材和底部区域与基线对照，避免把同一偏差复制到整组。检查在当前流程允许的阶段完成；若只能提交前核对代码，不能称原生视觉已通过。工具要求提交后停下或确认 QA 时，按该边界交付阶段状态，不擅自继续检查，也不把普通逐页提交额外变成用户审批。

## 6. 从局部核对扩展到全组

只读检查请求先列发现；已授权修复时按影响范围处理：

1. 修当前问题，例如缺失的分隔线。
2. 与用户提供的真实样式比较，判断是单一缺线还是整体菜单结构不一致。
3. 同类菜单统一；表单、确认框和结果提示各保留适用的结构。
4. 检查所有复用该区域的状态，尤其同一首页的菜单、纠错、删除和结果页。
5. 回读关键文字与图片，检查未涉及页面。必要时做同尺寸截图比较。

不要将“菜单文字居中”推广为所有表单正文居中；不要把透明成功提示也套成模态遮罩。

## 7. 完稿与交接

满足当前工具允许的验收路径后，按 [布局与验收](layout-and-review.md) 完成视觉检查。目标中存在可编辑画板、实际素材正常、入口和状态对应、底部控件不被裁切，才能说 UI 稿完成。

多页交付按真实操作顺序组织：入口、选择、确认、结果、返回使用；分支放在相应触发点，共用页面集中并注明路径，参考稿与主流程区分。若本次要求整理画板顺序，同步调整名称/编号和实际坐标，在画布总览核对顺序与重叠；索引排序不代替画板位置调整。文档配图沿用同一状态顺序。

如任务还包含 HTML 或文档同步，分别执行并记录结果：

- HTML：从真实入口操作，验证取消、返回及保存/删除后可见结果。
- txxprd：接收最终状态映射、截图和规则变化，再按授权范围替换文档图片或附件。
- 任一端未更新时，明确仍是哪一版，不把旧截图和新画板混成一份交付。

交接映射逐状态记录来源类型、版本／节点、最终截图和全部文档引用。缺图、来源矛盾和未确认入口列在对应条目；只读导出的图与已修改并核验的设计分开报告。
