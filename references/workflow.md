# 从需求到 MasterGo 完稿

适用于多状态绘制和按原稿补入口。局部修改不必重走整套流程。新页面生成先遵循 SKILL.md 中的工具路由，再在工具允许的阶段完成以下工作。

## 1. 分清输入分别决定什么

| 输入 | 决定的内容 | 需要核对的地方 |
|---|---|---|
| PRD | 功能、条件、权限、前后结果、验收边界 | 当前修订、被删除或划掉的规则、未决项 |
| 当前运行页面 / 交互手机 | 已有页面的实际结构、状态、控件及进入/返回 | 以运行页作基线时按[运行页面基线](app-baseline.md)读取；构建版本、逻辑尺寸与相关模拟条件 |
| 页面导航图（Atlas） | 定位页面、候选截图及关联源码 | 与运行页面分别核对版本；连线、调试和停用页不单独证明真实入口 |
| 对应源码 | 组件参数、素材、路由及条件的实现出处 | 是否为原始源码、是否对应当前构建、相关未提交改动及模拟分支 |
| 交互原型 | 入口、页面转换、返回路径、状态变化 | 是否只是演示开关；是否能从真实控件进入 |
| 用户指定的最终 UI | 结构、素材、组件、字体及视觉细节 | 来源文件/页面/节点、真实版本、同模块状态 |
| 现有 App 截图 | 当前菜单和控件形态的补充证据 | 平台、分辨率、系统栏；是否被用户指定为本轮基准 |
| 设计规范 / 组件库 | 可复用的 token 和组件状态 | 是否属于当前项目，是否被选中，是否与当前原稿冲突 |

当前运行页提供现状，当前确认决定本期变化。外部系统的行为按已确认结果呈现，未确定的依赖记录受影响的界面状态及待核实的问题。来源冲突时指出具体条目，通过实际内容与出处确认版本。没有规范的新项目记录当前设计授权和依据缺口。

只回填截图时，在指定文件、组或版本中按内容逐状态匹配。来源矛盾、图层误命名及缺图登记到具体状态。用户允许 HTML 补缺时使用已核对的对应状态并标明来源。只维护 HTML 的任务按该交付范围执行。

分阶段工作与 txxprd 共用记录，写清当前授权、规则来源与替代关系，以及受影响的状态和引用。续做前核对后续确认和目标最新版本，按当前允许的产物推进。旧入口、仅指定部分截图或暂未更新的附件逐项记录适用范围。用户暂停时保留准确的目标与进展。

### 先原型再同步

用户要求先根据现有设计调好 HTML、暂不写文档时，当前交付是可操作原型；使用实际素材和已确认规则，不提前写云文档或生成一整套新画板。后续明确要求同步后，以最后确认的 HTML 版本、命名、默认值和删除项为变更依据，读取最新来源与目标，再按当前工具流程生成对应原生状态并交给 txxprd。确认原型不等于可以重新设计其已认可布局，也不自动授权发布应用。

同步范围按真实操作路径确定，关联需求冲突时核对本入口的适用规则。各产物按[完稿与交接](#7-完稿与交接)验证。

## 2. 建立页面与状态清单

多模块任务先核对入口、操作对象、共用流程和返回。页面及导航按已确认的交互组织。

先把文档里的重复截图合并为状态，不机械地“一张图生成一页”。至少识别：

- 来源页面和触发入口；
- 操作菜单、编辑/选择、确认、结果；
- 取消或返回到哪里；
- 需求中确实存在的失败、空状态、选中/未选中和条件展开。

有多个入口或 Tab 时，沿各入口核对选中态、操作对象、页面外壳、状态和返回上下文。涉及多个对象时检查操作只影响已确认范围。

例如“删除一条内容”可以是：内容列表 → 真实更多入口 → 操作菜单 → 删除确认 → 列表移除及结果提示。是否需要原因、是否可跳过、是否保留原内容由 PRD 决定，不能由 UI 绘制者补造。

给每个状态稳定的序号、用途、来源及目标节点，明确哪些是已有页面副本、哪些是新增状态。所需画板数量由清单决定，不固定为案例中的数量。

- **能力联动。** 按操作前、触发时、进行中及结束后核对条件与结果。分别检查授权、使用资格、当前开关及其可操作状态。存在冲突或中断时，串联验证先前操作、后续动作、失败分支和返回或恢复；按钮样式、可用性和实际结果一致。
- **设置与状态标记。** 以当前规则核对标记依据、默认值、生效作用域和保存时机。从真实入口验证更改、失败、撤销或返回。外观修改保留已确认的行为，规则变更覆盖仍引用旧状态的位置。
- **分组和批量选择。** 明确显示、选择、计数和提交各自的单位。按已确认范围验证展开、分页前后、选择变化、各处理阶段及历史结果。使用容易辨认的摘要，具体字段和哪些记录纳入以本期规则为准。

### 媒体准备与可操作状态

按项目定义核对占位、预览、就绪、播放和异常的适用状态。分别验证资源、提示及控件行为随状态变化，尤其是预览已出现但主操作尚不可用的过渡状态。触发时机与动作结果采用本次确认。

### 菜单归类与入口迁移

调整“设置／我的”等菜单时，先逐项列出当前入口、用途、当前值或状态，再映射到新分组和完整路径。以用户要完成的任务及功能关联归类，分组名称应能预测里面的内容；参考其他产品的分类方法，不带入其独有功能。不能只为缩短首页把无关项装进同一组。

按本次要求控制菜单层级；已确认需要直接访问的入口保留，进入业务详情不机械计作新增菜单层级。逐项核对原入口是保留、迁移还是明确移除，记录共用入口和本期不上的功能，避免遗漏、重复或把未来能力画成本期可用。分组并不改变原有开关值、保存时机、权限和权益。

交付覆盖受影响的各层菜单、详情及返回。导航行保留实际去向，操作控件保留已确认的动作语义。HTML 从各受影响入口进入再逐级返回，检查末项可达、当前值和返回位置。

## 3. 锁定目的地与来源

用本次指示、PRD 和任务记录核对可写文件、实际页面树、父级及目标节点标识。同需求续做复用已登记画布，新需求按项目约定的层级和名称建稿。缺少约定层级时先核对授权范围。页面、子页面、画板按工具实际层级识别。

全新页面设计时，首个 MasterGo 动作按入口的 `design_page` 路由，在工具允许的阶段创建或切换目标。提交前记录并确认实际文件、页面名称与标识；把工具接受的精确标识带入生成/提交，工具不支持定位参数时通过原生界面确认当前位置。若工具自动落到其他页面，先纠正目标再写入；无法创建或定位时报告阻塞，保留已完成的需求整理，不向来源页或其他需求画布写入。

在任务记录中保存 PRD → 任务 → 目标文件/页面的映射，以及新建/复用理由，供后续续做判断。画布确认后再登记写入白名单。

来源图层只读。不要在来源页面调整大小、颜色、裁切、文本或实例状态。需要复制时，复制后立即回到目标，确认父容器、画板和新节点；不要使用剪切。

## 4. 建立视觉基线并应用 Taste

以运行页为基线时按[运行页面基线](app-baseline.md)锁定当前对应页面，再按 [设计师风格](designer-style.md) 提取同角色组件的原生属性及截图证据；以设计稿为基线时采用用户认可的最终稿。只有对比任务才与同页面/状态的 AI 稿配对。项目规范、获准新设计及同模块状态补充本次基线。只读回贴不重做风格设计。

调用入口中的 Taste 依赖与读取流程，按 [Taste 适配](taste-integration.md) 使用与页面类型相符的方法。Taste 用于判断层级与细节，字体 family 按 [字体统一规则](../SKILL.md#字体统一规则)；字号、行高、字重角色、配色和组件形态按项目基线继承。规范与当前指定稿冲突时记录具体属性；本次明确的局部修正直接按用户要求执行，其他未决差异不擅自扩展。

## 5. 选择最小改动的绘制方法

- 原页面只需补一个更多入口：复制完整原稿到目标，添加入口和新状态。
- 复杂头部已有准确图层：复制完整组并保持顺序、偏移、旋转和裁切，不重新拼近似图。
- 纯新状态：沿用同模块组件及 token，在当前工具流程中生成。
- 图片和图标已有素材：复用实际资产；占位图必须明确是草稿状态，不能当完稿。
- 用户要求独立副本：按 [素材与还原](assets-and-fidelity.md) 处理关联。

每个新页面单独提交。同类页扩展前，先将代表页的导航、字体片段、卡片角色、真实素材和底部区域与基线对照，避免把同一偏差复制到整组。检查在当前流程允许的阶段完成；若只能提交前核对代码，不能称原生视觉已通过。工具要求提交后停下或确认 QA 时，按该边界交付阶段状态，不擅自继续检查，也不把普通逐页提交额外变成用户审批。

## 6. 从局部核对扩展到全组

只读检查先列发现。获准修复时对照同类组件确认问题影响的节点和状态，再按[验收顺序](layout-and-review.md#验收顺序)逐项复核。

## 7. 完稿与交接

满足当前工具允许的验收路径后，按 [布局与验收](layout-and-review.md) 完成视觉检查。目标中存在可编辑画板、实际素材正常、入口和状态对应、底部控件不被裁切，才能说 UI 稿完成。

多页交付按真实操作顺序组织：入口、选择、确认、结果、返回使用；分支放在相应触发点，共用页面集中并注明路径，参考稿与主流程区分。若本次要求整理画板顺序，同步调整名称/编号和实际坐标，在画布总览核对顺序与重叠；索引排序不代替画板位置调整。文档配图沿用同一状态顺序。

同时交付多种产物时按当前授权的交付顺序执行。上游状态定稿并核对后再同步受影响的下游。

- HTML：从实际容器内的真实入口操作，验证本次涉及的返回、取消及结果。能力改为独立启用时从相关初始状态分别验证。移除旧操作或回执时，检查对应热区、键盘可达入口和后续画面。涉及超时重试时，验证迟到结果的影响。
- txxprd：接收最终状态映射、截图和规则变化，再按授权范围替换文档图片或附件。
- 任一端未更新时，明确仍是哪一版，不把旧截图和新画板混成一份交付。

交接映射逐状态记录来源类型、版本／节点、最终截图和全部文档引用。同状态各处复用已目检的定稿截图。缺图、来源矛盾或未确认入口写到对应条目。按[验证层级](layout-and-review.md#验收顺序)报告结果，实际应用及外部系统交互以各自的验证为依据。
