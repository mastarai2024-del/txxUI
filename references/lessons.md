# 两轮实践复盘

整理日期：2026-10-18。来源是一轮“从 PRD 绘制 MasterGo UI”的任务及随后一轮菜单修正与页面统一。业务名称、文件地址、账号、节点和素材均已脱敏。

案例包含 16 个页面状态。这个数量只是当时需求清单的结果，不能作为新任务模板的固定数量。

## 实际经过

1. **读取文档并确定设计来源。** 读取当前 PRD、原型状态与已有 UI；生成工具要求选择来源，用户选择自由绘制。这里的自由绘制仍要求忠实还原已有设计。
2. **锁定目标页面。** 用户明确所有新增内容只能放在测试页面及获准子页面，其他设计分类只能看或复制。之后生成和原生操作都以这条写入边界为准。
3. **拆成状态并逐页生成。** 按入口、操作菜单、编辑、反馈、删除、返回结果形成 16 个独立画板，文字和控件保持可编辑。
4. **处理本地素材导入失败。** 导入超时后先读取目标，确认是否只剩空占位框，再处理资源。生成阶段结束时只确认了画板存在，视觉验收尚未完成。
5. **修复灰框及素材依赖。** 后续发现临时资源引用未能稳定显示；两次局部替换受理后仍未生效。核实状态后改用原生复制实际图层，将图片、头像、标志和照片放到目标，处理了 57 处位图。
6. **验证副本独立性。** 只删除本次创建的临时来源副本，正式画板重新截图仍正常。真实来源页面始终保留。又发现一处头像副本不对，重新选源复制。
7. **恢复复杂原稿细节。** 用户指出头部不一致。对照原稿后发现完整背景、斜排文案、设备状态卡被简化；复制整组原稿到相关状态，恢复旋转、相对位置、图标和导航。
8. **修正底部布局。** 按原稿核对导航、手势条和可用高度；修复“跳过”被裁切及确认框底部留白。对所有画板重新截图。
9. **修复菜单细节。** 下一轮先补分隔线。用户给出现有 App 菜单后，进一步去掉冗余标题和空白，改为居中操作项、独立取消卡片及危险色。
10. **统一同类页面。** 检查 16 个状态，另改 9 个：两个操作菜单、五个表单弹层、一个确认框的遮罩和一个结果提示。表单继续左对齐阅读，没有全页居中。
11. **处理转换和队列问题。** 遮罩曾盖住菜单，拖动柄的对齐属性未生效，跨容器移动使取消按钮跑到上方。分别用实际层级核对、居中容器和局部位置修正解决；队列满时等待，并只重提明确被拒绝的请求。
12. **最终交付。** 更新后的画板逐页截图，核对文字和位图；7 个未改状态的截图保持一致。删除通用菜单标题等冗余内容时，确认关键后果仍在确认页保留。此次交付只覆盖设计稿，不能算作 App 或后端验收。

## 坑点与处理原则

| 坑点 | 本次观察 | 以后怎么做 |
|---|---|---|
| HTML 与 MasterGo 职责混淆 | 用户需要真实可编辑 UI，HTML 则需要能点击的流程 | 两种交付分别完成、分别验收 |
| 自由绘制被理解成自由发挥 | 只借配色仍会偏离原稿 | 记录完整视觉基线和用户允许的改动范围 |
| 目标页面未锁定 | 读原稿后容易在来源页继续操作 | 写入白名单，粘贴/提交前确认当前位置 |
| 页面、画板、文件混用 | “添加子页面”容易被误解 | 核实层级和父节点 |
| 只看首页 | 菜单、弹窗和表单与现有 App 不一致 | 查同模块其他状态和用户实际截图 |
| 用临时资源做长期图片 | 带版本的临时引用在本次流程中失效 | 真正导入素材或复制目标内图层，检查持久性 |
| 替换受理后没有效果 | accepted 与可见结果不一致 | 记录状态，回读后再决定重试或补位 |
| 原生复制选错层 | 一处头像副本异常 | 复制前看源，粘贴后核对内容和目标身份 |
| 拆散重画复杂组 | 背景、旋转文字、图标和状态卡遗漏 | 优先复制整组，局部增量修改 |
| 图层仍关联源组件 | 用户要求独立稿 | 仅在目标副本上解绑，记录实际检查范围 |
| 删除来源测试独立性 | 会破坏正式设计 | 仅清理获准的本次临时副本，再检查正式目标 |
| 固定高度过小 | 最后一个按钮被裁切 | 按换行、行高、间距、padding 计算实际高度 |
| 最小高度过大 | 确认窗留下大块空白 | 内容定高后在可用区域居中 |
| 混用平台底部距离 | 导航与系统区域容易叠加 | 使用目标平台和原稿尺寸，不照搬截图像素 |
| 分隔线遗漏 | 生成稿菜单层级不清 | 看真实截图，检查边框颜色、粗细及覆盖关系 |
| 菜单标题没有信息量 | 留白过大 | 经授权优化时去掉冗余，保留对象和必要说明 |
| 把菜单规则套进表单 | 长文和选项难读 | 按操作菜单、表单、确认、结果分别统一 |
| 修改遮罩改变堆叠 | 菜单也被压暗 | 回读实际顺序；修改后再截图 |
| align-self 没转译到画布 | 横线仍偏左 | 用充满宽度的居中容器，再确认位置 |
| 移动子节点改变顺序或 ID | 取消跑到上方 | 重新读取，必要时只在局部容器显式定位 |
| 大批请求挤满队列 | 后续请求被明确拒绝 | 小批次串行，等待排空，区分已受理与未提交 |
| SVG 哈希变化被当成换图 | 未改图标导出名变化 | 结合节点、样式和实际画面，不只比较文件名 |
| 旧截图混入最终交付 | 代码、画布和截图版本可能不同 | 从最终画布重取受影响状态，更新映射 |
| 把静态完成说成全部可用 | 未做 App、后端或实机检查 | 按证据层级交付，明确未覆盖项 |

## 哪些经验不应固化

- 16 张画板、57 处图片、9 个优化状态只是这次任务的数量。
- 手机尺寸、黑色主按钮、圆角、蒙层浓度、底部边距来自当时原稿；新项目重新读取。
- 工具队列容量、CSS 转译和生成后 QA 规则可能变化；执行时检查当前工具。
- 一个场景的业务限制不能变成所有产品的默认规则；从当前 PRD 读取。
