# 从设计师稿中学习可复刻的细节

适用于风格分析、设计师交接、对比 AI 稿，以及保留既有布局的视觉迁移。参数属于具体项目；本方法可跨项目复用。原始节点、截图、业务文案及精确来源映射保存在项目私有目录，公开技能只保留获准分享的提炼结果。

## 1. 明确迁移层级

先记录用户允许迁移什么：

- 信息结构与屏内布局：内容顺序、分组、主操作位置、密度。
- 画布编排：页面分组、阅读路径、状态排列。
- 微观视觉：字体角色、色阶、圆角、内边距、图标、素材处理、控件与状态。

“只学细节、保留布局”只迁移第三项。复制完整来源组仍是整页还原时的可选方法，不是风格学习的默认动作。文字按当前 PRD 校对；源稿错字、旧业务规则和示例数据只作为资料保留。

## 2. 建立节点级样本准入

使用 [风格档案模板](../templates/style-profile.md)。每个候选记录项目、文件/页面/根节点、作者归属依据、版本区域、用途、组件家族和截图。用途分为 `designer-final`、`spec`、`prototype`、`ai-comparison`、`legacy`、`uncertain`；只有前两种进入学习语料。

先遵从用户指定的来源与排除项，再核对实际区域和节点。AFTER / 最新版 V2 是定位线索：同页可能同时放着 Before、原型、AI 副本和旧组；同一 ID 前缀也不能证明同属新版。上方原型与下方正式设计分别登记；整页截图不能单独判定作者或版本。

按组件家族取样，覆盖本次用得上的表单、列表、菜单、确认框、结果、品牌素材及状态。共享组件的开/关、重复验证码页、同一列表的多个人物行，计为一个家族的多个状态。页面数量不等于独立证据数量。归属不清的页面先排除，继续分析明确来源。

只读任务可批量读取已经确定的根节点；保存一次原始响应，再在本地提取。缩略总览用于发现特例，随后查看代表页和有疑问的细节。无需为了学习导出前端工程、遍历团队库或读取所有图片。

## 3. 把观察变成量化证据

| 维度 | 记录内容 | 常见误判 |
|---|---|---|
| 字体 | 实际 family、角色、字号/行高/字重、颜色、换行 | 把规范表中展示标签的字号当成规范值；不核对中文字形回退 |
| 色彩与层次 | 背景、内容面、嵌套说明面、文字、语义状态、opacity | 只看根填充，忽略覆盖整屏的子层；把暖色小装饰推广为主按钮 |
| 几何 | 宽高、圆角、描边、内部padding、相邻gap | 把局部宽度或绝对y坐标当全局规范 |
| 图标与素材 | 可见边界、容器尺寸、裁切、描边、比例、旋转、混合 | 用通用图标替代品牌头像；将素材特例推广到所有头像 |
| 状态 | 默认、选中、禁用、按下、错误、离线、加载 | 用不同业务状态解释风格差异；把三种灰态合并 |
| 内容与边界 | 长短文、可读性、安全区、点击区域、返回及结果 | 为追求紧凑缩字；父容器正确却有子元素越界 |

每条数值标记来源类型：**图层明示**、**尺寸/坐标推导**、**截图估算**、**建议修正**。例如弹窗宽276、按钮宽228，可推导左右对称内缩24；前提是实际位置确实对称。截图像素需记录画板尺寸、导出倍率、视口与缩放，不能直接当设计单位。

缺失值明确记未知：SVG/组件引用可能隐藏圆角、描边或图标尺寸，CSS继承、透明度叠加与遮挡也可能改变实际画面。先读对应图层/真实资产或属性面板；没有证据时不补造精确参数。

本地属性清点：

```bash
python3 scripts/style_inventory.py \
  --manifest /path/to/private/sample-manifest.json \
  --output /path/to/private/style-inventory.json
```

manifest结构见模板，命令参数见脚本`--help`。它只读取显式批准的本地快照，不联网、不改画布、不输出业务文字或资产链接；统计出现次数与独立家族数，保留缺失项。工具不会自动将高频值认定为规范。

## 4. 形成项目规则与组件配方

每条规则写清 **角色 → 参数/关系 → 适用状态 → 来源家族 → 例外 → 验收方式**，并注明是观察结果还是新建议。

- 有明确规范且有实际组件佐证，可记为已确认规则。
- 无规范但在至少三个独立组件家族重复出现，可记为稳定候选；仍检查是否只是共用副本。
- 仅一个家族出现的做法，记为局部配方；相冲突的值保留模块变体，不平均成一个新值。

颜色按角色命名，字体按标题/正文/数字等角色选择。按钮、输入、列表、标签、菜单、弹窗、轻提示分别建配方，不把同一套容器套到所有页面。宽度按容器与边距计算；高度随内容增长。保留局部10px等经核实的例外，8px基准不等于所有尺寸必须整除8。

对比 AI 稿时同时记录 **已有一致项** 和 **可改进项**。先对齐组件意图、状态、文本长度和平台；区分样式差异与需求变化。已有尺寸和样式正确就复用，不为了体现学习重新设计。保留用户认可的布局和更易读的文字。

## 5. 用较少的重复读取保持准确

首次形成项目档案后，记录采样日期、来源身份、原始快照/截图指纹、规则别名与节点映射。续做先核对当前项目、版本区域和本次所需组件的少量锚点；未变则复用档案，变化则只更新受影响家族。无法核对当前来源时，说明采用的历史基线与未确认项。

绘制前列一张简短差异单：哪些参数复用、哪些是新状态、哪些需要修正。把档案中适用的组件参数直接带入当前工具允许的生成流程。只用本次所需的参考文件；Taste 在同任务内复用已读取内容，保持项目规范优先。

## 6. 在实际画布验收

当前工具允许检查时，回读实际节点并获取原生截图，逐项验证：

1. **范围**：屏内布局与画布编排只按授权改变；来源仍只读。
2. **属性**：同角色颜色、字体、字重、圆角、控件高度与配方一致。相同375单位画板上，建议核心几何偏差控制在1单位内；这是验收建议，不是测得的设计师习惯。截图估算值不按此容差硬判。
3. **关系**：内部对齐、左右内缩、文字换行、图标可见边界、按钮与安全区正确。系统区与所有底部子元素分别检查，缩略总览不代替细节。
4. **状态与内容**：默认/选中/禁用/按下分别正确，文案、危险后果和默认值按需求；不继承错字或错误动作名。
5. **实际观感**：真实素材没有占位或灰框，opacity叠加后仍清楚。正文可读性不足时采用明确记录的修正，而不是照抄小字淡色。

属性比对和离线脚本只证明参数记录与规则一致，不能证明画布或 App 通过。生成后的停止/QA门禁仍按当前 MasterGo 工具执行。HTML、文档和附件仅在本次授权范围同步，并单独报告版本与未同步项。
