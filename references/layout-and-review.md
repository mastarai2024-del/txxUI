# 布局统一与视觉验收

使用项目的实际设计基线。下述尺寸公式可复用，案例里的按钮高度、圆角、蒙层浓度及画板尺寸不可直接推广到所有项目。

## 区分控件用途

| 类型 | 检查重点 |
|---|---|
| 操作菜单 | 与同模块真实菜单相同的对齐、行高、分隔线、取消分组和危险操作样式 |
| 表单弹层 | 标题与说明便于阅读；选项和输入区完整；提交与取消层级清楚 |
| 删除确认 | 对象、后果、默认选择、原因是否选填、保留内容的同意项符合 PRD |
| 提交结果 | 轻提示还是模态对话框由交互决定；不要无意添加阻断式遮罩 |

一次菜单优化不能改变删除语义、原因是否必填、隐私同意或风险提醒规则。不要为了视觉整齐删掉必要警告。

## 操作菜单

用户给出了居中文案的底部操作卡片时，同类菜单可统一：

- 操作项居中，分隔线保持一致；
- 删除操作使用项目危险色；
- 取消单独成卡片，与操作项之间留出明确间隔；
- 去掉无信息量的通用标题和空白占位；
- 人物、照片归属等有助于确认对象的信息可以保留为紧凑说明；
- 次要解释居中且比操作名弱，但仍需可读。

保留表单的阅读结构。不要把操作菜单的整套外观强行套到长说明、原因选择和编辑页。

## 重复主动作

同一业务动作只保留一个主入口。编辑页同时出现顶部文字“保存”和底部主按钮“保存修改”，即使两个入口功能相同，也会让用户不知道应该点哪个；应保留层级更明确的一个，通常优先底部主按钮。

删除顶部入口时，如果标题通过左右元素分配空间来居中，应在原位置放等宽占位，再回读标题和按钮位置。不能只删文字后留下偏移的标题。完成修改后同步检查 MasterGo、HTML 和文档中的同一状态，避免只修设计稿、附件仍显示两个按钮。

## 计算底部位置

设画板高度为 H：

- 贴底弹层：`top + height = H`；底部安全空间包含在弹层内。
- 浮动操作卡片：内容底边不进入项目的安全区 S，通常满足 `top + contentHeight <= H - S`。
- 居中确认框：在适用的可用区域中居中，先按内容计算高度，再定位。
- 绝对定位子元素：逐个检查 `child.top + child.height <= parent.height`，以及最终屏幕坐标不越过画板底和手势条安全区。父容器高度正确，不代表取消按钮或手势条没有越界。

内容高度包含实际换行、各行高度、padding 和 gap。检查最底部“取消/跳过/保存”是否完整可见，不能只检查容器边界。不要重复计算系统栏与应用导航，也不要拿 Android 截图的像素距离直接套到 iOS 画板。

案例中曾出现弹层过矮裁掉“跳过”，以及确认框最小高度过大造成底部空白。修复依据是内容高度和原稿的系统区域，不是统一把所有弹层设成一个固定高度。

## 拖动柄居中没有生效

实践中，单独给小横线加 `align-self: center` 没有转换成预期的画布布局。可将原位置的容器改为充满内容宽度、横向居中，内部保留固定宽度的小横线。

新结构示意（尺寸仅示例）：

```html
<div data-name="拖动柄容器"
     class="flex flex-row justify-center items-center self-stretch h-[4px]">
  <div data-name="拖动横线"
       class="flex flex-row justify-center items-center w-[36px] h-[4px] bg-[#D9D9D9] rounded-[8px]"></div>
</div>
```

修改既有图层时，以真实快照保留其他属性；尽量复用原拖动柄的位置作为容器，避免新增同级容器被排到按钮后面。最后检查画布位置，而不是只看代码中有“center”。

## 层级和顺序

- 修改遮罩后可能改变它在画布中的层级；检查它是否压暗菜单本身。
- 跨父容器移动“取消”后可能出现新 ID 或意外顺序；回读后再处理，不用旧 ID 继续盲改。
- 先尝试工具当前支持的正常重排；仍无法正确转换时，可以在这个已确认尺寸的局部容器中显式定位，并保留节点，随后检查整体位置。
- 显式坐标只能解决该固定画板的局部问题，不能据此宣称响应式或其他尺寸已通过。
- 不要为修一个顺序问题全量替换整页，也不要把所有图层都改成绝对布局。

## 验收顺序

在工具允许检查的阶段：

1. **结构**：目标节点和页面归属、文字可编辑、图片节点、关联实例和关键属性。
2. **逐页截图**：素材是否真实显示，菜单文字、分隔线、遮罩、裁切、底部按钮和手势条是否正常。
3. **同类对照**：主/次按钮、选中态、菜单与表单的对齐和间距是否一致。
4. **内容回归**：文字、默认选择、危险操作、原因选填和同意项是否被误改。
5. **关联页面**：所有复用受影响区域的状态。批量统一时，可对未改页面做同尺寸像素比较作为补充。
6. **跨端同步**：MasterGo、HTML、文档文字、文档图片和附件对应同一版本；图片 token、附件 token 和必要哈希与本地文件一致。

总览图用于找异常，发现细节疑问时放大对应单页。截图数量、文件非空、像素一致或工具 success 都不能单独替代这些判断。

交付口径分开记录：已提交、节点已回读、视觉通过、素材独立性已验证、HTML 交互通过、文档同步通过、真实 App 验证。没有执行的项保持未验证。
