# 布局统一与视觉验收

使用项目的实际设计基线。下述尺寸公式可复用，案例里的按钮高度、圆角、蒙层浓度及画板尺寸不可直接推广到所有项目。

组件的比例、字形、图标、四边描边及实例继承见[组件外观与实例](components-and-instances.md)；层级、固定/撑开/填充及内容变化见[自动布局](auto-layout.md)。只加载本次受影响部分，既有位置公式和局部修正方法继续适用。

## 区分控件用途

| 类型 | 检查重点 |
|---|---|
| 操作菜单 | 与同模块真实菜单相同的对齐、行高、分隔线、取消分组和危险操作样式 |
| 表单弹层 | 标题与说明便于阅读；选项和输入区完整；提交与取消层级清楚 |
| 删除确认 | 对象、后果、默认选择及已确认的输入和同意项符合 PRD |
| 提交结果 | 轻提示还是模态对话框由交互决定；不要无意添加阻断式遮罩 |

## 新增操作的位置与含义

给已有页面补下载、分享等小操作前，核对当前页面及已确认的其他需求：哪些位置已有或即将放置控件，哪些状态会占用该区域。位置冲突不靠“当前图上没有”排除；用户已指出占用时，采用获准的新位置并同步相关状态与文档引用，不移动其他需求的控件。

次要操作沿用同模块图标按钮与间距，不自动做成大块主按钮。图标视觉尺寸与触控范围分别检查；缩小图形后仍要符合项目热区要求，不能把某次确认的像素值推广为统一规范。

图标与标签共同说明对象和实际结果。相似动作作用于不同对象时，用读者能区分的形态或标签。窄屏下核对标签、数值与标题之间的空间。

## 折叠摘要与展开状态

接入现有区域时保留获准范围以外的结构。按当前规则确认折叠态应保留的摘要和提示、展开入口及收起行为。

分别检查折叠与展开时的内容、控件和相关状态。用最窄目标宽度验证摘要不会挡住操作，展开后重点内容仍可达。从真实入口打开再返回，核对状态是否按约定保留。

综合入口用能概括实际用途且符合产品定位的名称。名称确定后核对相关控件、提示和文档引用。

## 紧凑列表与状态可读性

用户要求一屏多放条目时，先保留用于辨认对象的内容、时间和操作，再压缩重复标题、标签、卡片边距与无信息空位；不以缩小字号、点击热区或截断必要后果换密度。排序所用时间与行内显示时间分别遵从 PRD，不能为了单行改动业务含义。

列表行、操作区与结果页的历史参数从当前项目记录查取，复用前对照同模块组件。

1. **长内容避让。** 按真实可用宽度检查时间、标题、状态文字、勾选框和箭头；长标题省略不能挤压固定状态或控件。图标、混排文字与按钮按基线和可见中心核对，不仅看容器坐标。
2. **状态易识别。** 状态符号难以辨认时用清楚的文字辅助。涉及编辑和历史时，按已确认的状态条件与保存规则核对输入、清空、再次进入及历史回显。
3. **滚动与底部。** 用本次需要的长标题、不同内容类型及足够长列表检查实际滚动容器；列表末项、展开输入区、底部按钮和安全区可到达，没有被遮住的半行。多屏样例只服务本次验证，不成为所有原型固定数量。
4. **同一操作贯穿状态。** 按各阶段的快照规则核对所选对象、字段和计数。样例或状态改动后统一核对获准交付的原型、原生图和文档。

按[验收顺序](#验收顺序)逐状态核对布局，并对照实际组件的边角与贴底方式。

## 操作菜单

同类菜单沿用认可组件的对齐、分隔、取消及危险操作样式。表单和确认窗沿用各自的层级，必要说明按[操作需要](#操作文案按决策需要出现)保留。

## 修改前后配对

已有页面确有视觉修改时，按受影响状态配对修改前／后原生截图；先核对页面、状态、逻辑尺寸和导出倍率。两张图片像素尺寸相同只是技术检查，不证明页面或状态匹配。新增页面和缺失前图单独说明，不用旧需求或近似页补成“修改前”。只读导出与回贴不要求制作前后图。

在项目私有目录建立 JSON，路径相对该 JSON 所在目录解析；示例名称与变化说明不构成产品规则：

```json
{"pairs":[{"state":"settings-open","before":"before.png","after":"after.png","changes":["调整已确认的标签文案"]}]}
```

```bash
python3 scripts/contact_sheet.py --pairs /path/to/review/pairs.json --output /path/to/review/paired.png
```

每个状态占一行，左侧 BEFORE、右侧 AFTER；完整状态名、变化说明、原图尺寸和哈希写入同名 JSON 索引。不同状态可以有不同尺寸，但每对前后图必须一致。尺寸不符、重复状态、缺图或覆盖源图时工具报错，先核对来源，不强行拉伸截图使其通过。工具保持原图，只等比缩小评审副本；输出已存在时需显式 `--overwrite`。

逐对目检实际文字、素材、遮挡、换行及底部控件，并检查未授权区域是否变化。配对图与变化说明用于审阅，不能自动判定视觉合格，也不替代单页检查、图层回读或实机交互。

## 同一组输入的状态对照

需要在需求文档解释不同操作如何影响结果时，用已确认的同一组输入和顺序画一张对照图。每种操作写明选中对象，并另用文字、边框或区间带标出实际结果，使读者能独立读出选择状态和结果范围。

- 涉及时间范围时复用同一条时间轴，逐组标出范围端点。重叠记录确实会进入多个结果时，用独立行和文字标明各自包含及重复次数。
- 按文档实际列宽检查文字、端点、图例和重叠标记。横排难读时，将场景上下排并保持同一尺度。回贴时核对规则所在行和实际呈现。
- 这类交付使用标明用途的规则示意图。源画板和主流程图以本次授权的交付范围为准。

## 操作文案按决策需要出现

按钮、Action Sheet、更多菜单和快捷操作默认使用简短、明确的动作名称。先改进名称，再判断是否确实需要说明。不要为了显得完整，在每个动作下放一行灰字，或把同样解释搬到 tooltip、信息图标中。

逐条判断辅助文字的用途：

| 用途 | 处理 |
|---|---|
| 重复动作或解释常见词 | 保留明确的动作名 |
| 标识当前操作对象 | 上下文不足以辨认时保留一处对象说明 |
| 不可逆后果、费用、权限或影响范围 | 保留作决定所需的信息。详细后果优先放在既有确认步骤；若当前菜单就是执行前最后一步，保留当前必要警告 |
| 设置当前值、用于区分选项的实质差异、表单帮助或错误 | 按各自组件规范保留；不把它们当作冗余按钮说明删除 |

按当前需求确认后果与确认步骤。已有确认步骤已清楚解释后果时，精简菜单里的重复说明。

同一组通用说明只出现一次，放在组级标题或正文；特定操作才有的信息靠近该操作。必要提示需在触屏上直接可读，不能只依赖 hover。明确要求的说明、无障碍名称和必要警告均保留。

一次确认同时影响多项能力时，在标题点明操作，用简短分组说明开启后可用的能力和使用期间的限制。会在特定条件下中断的结果跟触发条件写在一起。每项含义应从文字直接读懂。只有勾叉含义明确且一致时才保留图标，含义混杂时改用分组及短句。主按钮写将执行的动作。

验收时为每条辅助文字回答“删掉会让用户缺少什么判断依据”。答不出具体依据的，删除并重新计算行高、留白与弹层高度，沿用项目点击热区及安全区。不能只隐藏文字、保留原来的双行空位。逐项回看实际截图；结构检查和工具 success 不能自动证明文案合格。

## 指标说明与横竖屏

- 指标卡有独立说明入口时，从各卡打开，检查名称、单位和当前筛选下的数值是否对应。次数说明按什么去重，人数说明按谁去重，比例写清分子与分母。切换卡片或筛选后复核说明是否随之更新。
- 同一确认弹窗需要覆盖横竖屏时，从各方向的实际入口触发，核对定稿文案、按钮是否可见可点，并分别检查取消、确认后哪些功能继续、哪些停止。交付配图从各自状态取图，按文档约定的顺序回贴。

## 计算底部位置

设画板高度为 H：

- 贴底弹层：`top + height = H`；底部安全空间包含在弹层内。
- 浮动操作卡片：内容底边不进入项目的安全区 S，通常满足 `top + contentHeight <= H - S`。
- 居中确认框：在适用的可用区域中居中，先按内容计算高度，再定位。

内容高度包含实际换行、各行高度、内边距和间距。检查底部操作是否完整可见，并按目标平台的系统栏与导航计算安全空间。

## 拖动柄居中没有生效

实践中，单独给小横线加 `align-self: center` 没有转换成预期的画布布局。可将原位置的容器改为充满内容宽度、横向居中，内部保留固定宽度的小横线。

新结构示意（尺寸仅示例）：

```html
<div data-name="拖动柄容器"
     class="flex flex-row justify-center items-center self-stretch h-[4px]">
  <div data-name="拖动横线"
       class="flex flex-row justify-center items-center w-[36px] h-[4px] bg-[#D9D9D9] rounded-[8px]"></div>
</div>
```

修改既有图层时，以真实快照保留其他属性；尽量复用原拖动柄的位置作为容器，避免新增同级容器被排到按钮后面。最后检查画布位置，而不是只看代码中有“center”。

## 层级和顺序

修改画板高度可能触发既有约束，改变子层的相对位置、蒙版或图片裁切。先只改根尺寸，再回读受影响子层；需要移动的按钮、文字和头像优先单独修改。保留图片源，不为调整位置重传素材。

- 修改遮罩后可能改变它在画布中的层级；检查它是否压暗菜单本身。
- 跨父容器移动“取消”后可能出现新 ID 或意外顺序；回读后再处理，不用旧 ID 继续盲改。
- 先尝试工具当前支持的正常重排；仍无法正确转换时，可以在这个已确认尺寸的局部容器中显式定位，并保留节点，随后检查整体位置。
- 显式坐标只能解决该固定画板的局部问题，不能据此宣称响应式或其他尺寸已通过。
- 不要为修一个顺序问题全量替换整页，也不要把所有图层都改成绝对布局。

## 验收顺序

在工具允许检查的阶段：

1. **结构**：目标节点和页面归属、文字可编辑、图片节点、关联实例和关键属性。按[字体统一规则](../SKILL.md#字体统一规则)回读文字片段的实际 family 和字重。
2. **逐页截图**：素材是否真实显示，菜单文字、分隔线、遮罩、裁切、底部按钮和手势条是否正常；字体有无缺字或回退，混排基线、间距、换行与裁切是否正常。
3. **同类对照**：主/次按钮、选中态、菜单与表单的对齐和间距是否一致。
4. **内容回归**：文案、默认值、操作条件和结果是否符合当前需求。
5. **关联页面**：所有复用受影响区域的状态。批量统一时，可对未改页面做同尺寸像素比较作为补充。

总览图用于找异常，发现细节疑问时放大对应单页。截图数量、文件非空、像素一致或工具 success 都不能单独替代这些判断。

发现错位、倾斜、重叠或缺图后，核对实际原生页面及相关父容器、图标／文字的旋转、对齐、基线和系统栏，修复后检查复用该区域的状态；不能只修用户圈出的一张。用户明确要求重查全部 UI 时按本次状态清单逐页目检，缩略总览只用于定位，不凭一页抽样宣称全过。全量复查的范围仍限本任务，不扩到无关画布。

交付口径分开记录：已提交、节点已回读、视觉通过、素材独立性已验证、HTML 交互通过、文档同步通过、真实 App 验证。没有执行的项保持未验证。
