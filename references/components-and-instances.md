# 组件外观、属性与实例继承

用于复用或调整组件，以及用户明确要求的组件化、母版联动和界面关联。视觉依据沿用[设计师风格](designer-style.md)，尺寸行为按[自动布局](auto-layout.md)处理；小改单个实例只读相关部分。组件数量、原生类型与外观质量分别判断。

## 1. 先确定实际要继承的外观

在当前工具允许读取的阶段，从已锁定基线中选同模块、同角色、同状态的真实母版或已确认控件，核对文件、版本与实际节点。保留一份按逻辑尺寸可查看的样图，读取原生属性；不靠组件名称、色板或文字形容重新猜一套。

在现有项目记录中，只登记本次用到的样板、适用状态、字体层级、颜色、形状、间距、图标与尺寸规则。区分来源取值、获准变化和未知项；字体 family 继续遵循[统一规则](../SKILL.md#字体统一规则)。真实参数、节点与图片留在项目中，不写成通用常量。

优先完整复用已确认组件的容器、文字、图标和素材。有新结构时，从同类角色组合；没有直接样板时采用当前模块可核实的角色关系，先验证代表组件，再推广。只在缺口会改变方向时澄清，不因缺少完整组件库阻塞有依据的局部修改。

## 2. 先看组件本身的比例与细节

| 角色 | 画面上要核对的关系 | 常见偏差 |
|---|---|---|
| 按钮、选项 | 主次层级、文字基线、图标与文字的间距、两侧留白、实际视觉居中；同角色状态的形状与对齐稳定 | 只居中外框，字形仍偏；所有按钮强行同高同宽；禁用与未选中混淆 |
| 勾选框、箭头、状态图标 | 沿用真实矢量、线性/实心、线宽、端点、灰度和视觉中心；图形大小与触控范围分别核对 | 用字符或近似库图标拼装；填充导致圆变椭圆；图形缩小连带缩小热区 |
| 页签、选择项 | 文字基线、选中标记、分配宽度、内边距及与内容区的距离 | 固定两列宽度只适配一张图；选中后文字或下划线漂移 |
| 记录、卡片、备注 | 普通/展开/只读各有清楚边界；时间、摘要、标记与箭头对齐；背景、文字和四边描边属于对应容器 | 每行都加重卡片；展开只剩底边线；长标题挤掉状态；只读照搬输入外观 |
| 弹层、输入 | 顶部/底部各角、标题与关闭、输入留白、遮罩和底部操作关系 | 将弹层圆角推广到普通卡片；整页都套同一个半径；操作或手势区裁切 |
| 进度、结果 | 图形与文字层级、状态与对应对象邻近、语义色与文字一致；列表摘要和完整面板按各自空间组织 | 用近似符号替代真实结果资产；列表硬塞完整面板；只换颜色却保留相反状态文字 |

先收敛结构、比例和锚点，再修字体、灰度、形状与图标细节。按实际尺寸看字形与留白，局部放大用于排查，不能只看总览缩略图。已有正确部分保留，不为体现优化改掉所有尺寸、分隔线或圆角。

## 3. 把外观状态与内容属性分清

先盘点真实出现位置、变化维度、当前母版及目标实例，只覆盖本次需要的组合。

| 变化 | 使用方式 |
|---|---|
| 有依据的外形、用途、展示模式或状态 | 用当前工具支持的变体，维度保持同一含义；不同尺寸结构可拆展示变体或独立组件 |
| 时间、昵称、摘要、按钮文案、备注、数量 | 绑定文字属性或保留可编辑字段；不同记录不各造一个变体 |
| 可选图标、说明、备注区 | 用显隐属性并核对隐藏后的空间折叠；是否可隐藏由需求决定 |
| 允许替换的图标或子控件 | 使用受支持的子实例替换，保留尺寸、对齐与来源约束 |

选择、展开、有无备注、编辑/只读分别理解，按 PRD 核对有效组合和依赖。不从单张样例推导自动勾选、清空或保存；不要补无依据的状态，也不要穷举所有理论组合。动态混排优先保留可编辑文字片段；确需拆字段时见[动态文字](auto-layout.md#动态文字与字体)。

## 4. 复用与建立母版

已有合适组件先复用。**只有用户明确要求主组件、组件集、变体、可复用组件或抽组件时，才进入创建流程**；普通新页、外观优化和局部修改不自动授权建库。用户同时要求页面与抽组件时，先按当前页面生成协议完成页面，再基于真实节点执行组件步骤。

创建或修正母版按[工具路由](mastergo-tools.md)和本轮组件规则执行。真实类型应为原生 Component/Component Set，变体属于正确组件集；名称、普通分组、边框颜色或截图不能代替关联。先稳定基础按钮、勾选框与箭头，再组合卡片等结构，需要统一维护的子控件保留为真实子实例。

保留真实图层和尺寸规则，核对文字/显隐等属性绑定。结构调整后刷新快照与属性定义，使用当前标识验证，不能长期缓存旧属性 ID。母版完成和页面已采用分别记录，展示母版不等于已关联页面，也不自动发布团队库。

创建或重绑文字属性后，重新回读受影响文字节点及片段的 family、字号、字重和行高，再看实际字形；属性绑定可能使原有文字样式回落，创建前字体正确不能证明创建后仍正确。修正时保留属性关联与内容覆盖，不逐实例写死样式来掩盖母版问题。

仅改文字时优先更新现有文字节点，保留节点标识及绑定。确需替换文字子树时，先保存绑定关系，写后刷新快照并实际修改对应属性，确认页面文字仍随属性变化；文本当前显示正确不证明绑定未丢失。

## 5. 按范围关联实际页面

1. 判断本次改的是单个实例、某个变体、本页同类控件还是共享母版；沿用[共享关系与修改范围](assets-and-fidelity.md#共享关系与修改范围)，不扩大传播。
2. 按界面真实内容与状态选母版/变体。优先用当前工具支持的换母版能力；必须替换时记录原节点到新实例的映射。
3. 保留每条记录的文案、数值、显隐、选中状态及已有原型关系。保留固定、撑开、填充规则，不能只恢复原宽高。
4. 区分数据覆盖与样式覆盖。仅清理本次统一样式所需的旧字体、颜色或尺寸覆盖，保留不同记录内容、已确认单例差异及并行编辑；不全量重置或批量解绑。
5. 检查相关页面、弹层背景与嵌套实例。只改一处时不迁移其它页面；已要求统一时不能只在旁边建母版而漏掉实际位置。

## 6. 分别核对外观、属性与继承

在本轮工具允许验收的阶段检查；需要独立 QA 选择或停止时沿用现有门禁，不换通道绕过。

- **外观：** 按同逻辑尺寸对照样板，检查本页第二节中的比例、锚点、字形、图标、边界、素材及底部区域；内容不同的区域不靠像素相似率判好坏。
- **结构：** 实例实际指向正确母版与变体；复合组件里的基础控件仍为正确子实例，文字可编辑。
- **数据与状态：** 在实际实例或可恢复副本中修改本次相关文字、显隐和变体，观察真实结果。记录数据相互独立，状态文字与图形一致，长内容与折叠按[布局核验](auto-layout.md#有意义的布局核验)处理。
- **继承：** 对共享样式变更核对代表实例及必要嵌套层。需要探针时，在授权内使用可恢复副本或受控修改；恢复测试样式与文案，保留期间的有效编辑。既有关联只读核对不要求额外改母版。

外观通过、母版完成、页面关联、组件属性行为、原型点击及真实 APP 各自报告。本地结构或走查不能代替实际画布效果；用现有任务记录保留证据和未验证项。
